GIT, COMMIT AND CI RULES

3. Commit after EVERY change that leaves the tests you touched green. Stage only your files, by name (never git add -A or git add .). Message: "[B1][<task id>] <what changed and why>". Then: git push --force-with-lease origin lane/b1.

5. Never push or force-push Main. Never commit .env, secrets, *.csv or reference_documents/. Never touch frontend/ or web/app/.
6. If a test fails after a rebase, check whether it also fails on origin/Main. If it does, it belongs to another lane: note it under "Failing tests seen" in your HANDOFF lane section and carry on. If it fails only with your change, fix your change.
7. If a fix needs a file or region you do not own, do not make it. Add it under "Requests for other lanes" in your HANDOFF lane section, commit, and move on.
8. If something outside the code blocks part of a task (VPN, a data-team reply, a user decision), do every other part, commit it, record the blocked part, and start the next task. Never sit idle and never guess a decision.
