Megh One AI: full system audit

Date: 23 Oct 2026 Branch: update/2026-10-22 @ 6c95632 Server checked: :8401 (live) Scope: backend, AI pipeline, models, UI, security, tests, docs, process

Short answer: the system works, but it is not perfect. The database, vector store, app server and all five model roles are up. The automated suite is fully green, and whenever the bot gave a figure in my live tests it matched the database. The problems are elsewhere:

  • Understanding the question. Small wording changes ("five" instead of "5", "FY24", word order, Hinglish) can still send a question down a different path. The result is a clarifying question, a refusal, a wrong year or, in known cases, a different number.
  • Data protection. Bank-account data is still in git history, and a second copy sits unprotected in the working folder.
  • UI. Headline figures are cut off on phones, and one comparison card is misleading.
  • Workflow. About 3,500 hand-written phrase rules, no accuracy benchmark run on every change, and docs that no longer match the code.

Where the wording changed the outcome (found live today)

High"FY24" is read as FY 2024-25
Q: MGNREGA person-days in West Garo Hills in FY24 A: West Garo Hills recorded 2,808,417 person-days … in FY 2024-25.
Expected
In Indian government use, FY24 means FY 2023-24 (5,489,616). "FY 2023-24" gives the right answer. The MGNREGA report already found this, but it has no KI number.
Fix
One deterministic year parser for FY24, FY'24, FY 23-24 and 2023-24, used by every stage, with a unit test per format.
Medium"Five highest" ignores the word "five"
Q: Five highest blocks for MGNREGA person-days in West Garo Hills, 2023-24 A: How many results should be returned — the top 3, the top 5, the top 10, or the complete list?
Cause
The top-N rule looks for digits only (context_policy.py:277). "Top five" happened to work through another path; "five highest" did not.
Fix
Normalise number words ("three", "five", "ten", "dozen") to digits once, before any rule runs.
MediumThe same answer comes in different units
"ri bhoi focus plus amount disbursed all years" → ₹5,237,500.00 "What is the total amount disbursed under Focus Plus in Ri Bhoi…" → ₹0.52 crore
Impact
Both are correct, but an officer comparing two answers sees two different-looking numbers. The bare rupee value is also shown with Western digit grouping (52,37,500 would be the Indian form).
Fix
Format money in code after the composer: crore above ₹1 crore, lakh below, always in Indian grouping.
MediumWhether you are refused depends on the wording
As a state officer: "Top 5 blocks by … in West Garo Hills" → "Your account is authorised up to district level." Same user: "Five highest blocks for … West Garo Hills" → asked "top 3/5/10?" first
Note
The refusal itself is by design: state_officer is capped at district level (app/auth.py:64), so a state officer sees less detail than a block officer. Please confirm that this is really the intended policy. A state-level officer would usually be expected to see blocks and villages. If it is intended, the refusal should come before any clarifying question.
Low"in 2023" asks which financial year
Note
That is a reasonable answer (2023 spans two FYs). Chips with 2022-23 / 2023-24 would be quicker than a free-text question; today it comes back with no chips.
LowAPI calls with no session id all share one all-day conversation
Evidence
routers/query.py:144-155 buckets them as day-<user>-<date>. In testing, "How many houses?" was answered from another question's context ("PMAY-G … FY 2024-25: 0 houses") instead of being asked. The chat UI is not affected, because it creates a session per chat. Scripts, integrations and testers using the API are.
Fix
Give each session-less call its own one-off session, or reject calls without one.

Why this keeps happening (root causes)

  • About 3,500 hand-written phrase rules. The pipeline decides routing, ranking, years, places and follow-ups with word patterns: 551 Matcher, 1,555 W(…), 948 Seq, 519 Alt, across 36 files. Each rule was added for one reported sentence, so a new wording that no rule anticipated falls through to a different path.
  • The same idea is listed in several places, and the lists disagree. The superlative words are defined separately in context_policy.py:272, c12_answer_shapes.py:44 and cross_figures.py:166. Only one of them knows "max/min/greatest", and only one knows "poorest".
  • The model output varies a little even at temperature 0. vLLM batching is not bit-exact, and no seed is sent. That explains the "1 in 7" and "1 in 20" wrong-number cases.
  • No paraphrase benchmark runs on every change. Fixes for one wording can silently break another, which is what happened with the Focus Legacy constituency regression.
  • Seven behaviour decisions in one day (D-060..D-066), some reversing each other. The CM Elevate rule changed on 12, 19 and 22 Oct. Each change moves answers that used to be stable.

UI issues

I checked the live app at 390, 820 and 1440 px with a headless browser and read the React source. The page never scrolls sideways, there were no script errors, and the served build matches the source.

Fix
Below about 480 px, show one card per row or wrap the values; never put an ellipsis on a number.

A misleading "% ahead" verdict. The answer text repeats it: "MGNREGA has the most money … 1.66x".

Show no verdict when the measures differ in kind, and label each tile ("spent", "released"). Add a regression test next to the KI-397 test.

Security and data protection

CriticalUnmasked bank account numbers are still in git history on Bitbucket KI-022
Evidence
Commit 7064ab6 added Focus Legacy to share to BLH.csv (account numbers, holder names, IFSC). It was deleted later, but it is reachable from origin/Main and four other remote branches.
Fix
Purge it with git filter-repo or BFG, force-push, ask Bitbucket to run garbage collection, and have everyone re-clone. Inform the data owner.
CriticalA second copy of the personal data is one git add . away from being committed again
Evidence
raw_uc/ (82 MB) is untracked and not in .gitignore. It holds the same bank-account CSV, the CM Elevate CSV (applicant names) and Focus Plus Master (phones, voter IDs). new_docs/*.csv (14 MB) is not ignored either.
Fix
Add raw_uc/ and new_docs/*.csv to .gitignore today, and move the raw data out of the repo folder.
HighModel-written SQL runs as the main DB login, with superuser allowed KI-004, KI-304
Detail
READONLY_DATABASE_URL is not set, and READONLY_DB_ALLOW_SUPERUSER=true. The SQLGlot guard is strong: one statement, SELECT only, privacy tables blocked, LIMIT added, READ ONLY transaction. But it is the only barrier.
Fix
Get the megh_readonly password from the ingestion team, set it, and remove the superuser allowance.
HighCertificate checking is off for every model call llm.py:42-78, KI-015
Detail
.env points to certs/enlight-aiops-internal-ca.pem, but that file does not exist, so the app silently uses verify=False. API keys, questions, SQL and result rows travel without certificate checks.
Fix
Install the CA file, and refuse to start when a configured certificate file is missing.
HighQdrant is on a public IP with no API key KI-200
Impact
Anyone who can reach port 6335 can read or delete the knowledge base and the stored chat-memory vectors.
Fix
Set an API key and firewall the port.
MediumCredentials in tracked files and the git remote
Detail
app/users.yaml (tracked) holds 2 plaintext seed passwords (KI-023), and .git/config holds a Bitbucket token inside the remote URL. Rotate both: hash or remove the seeds, and use a credential helper.
MediumThe bootstrap endpoint can always create a super admin routers/auth.py:98-104
Fix
Disable it once users exist, and use a constant-time token compare.
MediumLimits and caches are per worker; no Redis
Detail
With 2 VMs × 2 workers, the login throttle is effectively 24 tries per 5 minutes, up to 96 model calls can run at once, and a cached answer on one worker is a miss on another. TRUSTED_PROXIES trusts all private ranges, so VPN users can spoof their IP.
MediumSafety checks fail open silently
Detail
If the guardrail model or the SQL verifier times out, the answer goes out unchecked, with no alert. There are no retries on brief 502/503 errors, and 199 broad except Exception blocks hide failures.
LowSemantic-cache key is coarse (risk, not reproduced live)
Detail
The cache match uses scheme, place and year plus a 0.93 similarity score, and does not include the metric or direction. The code reviewer measured "top 5" vs "bottom 5" at 0.95 similarity, and "completed" vs "sanctioned" at 0.94. My live top-3 / bottom-3 test answered correctly.
Fix
Add metric, direction and numbers to the cache key, or raise the threshold to at least 0.97.

Workflow mistakes and how to fix them

HighAccuracy is measured by hand, after the fact
Now
Test sheets are run ad hoc with scratch scripts kept outside the repo. The 74-question eval hasn't run since 18 Oct. Regressions (55/55 → 11/55) were found days later by testers.
Suggest
Build a golden set: around 300 questions, each with 3–5 wordings (including tester wording, Hinglish, abbreviations and number words) and DB-computed answers. Check it into tests/, run it on every merge (it needs the VPN, so use a nightly runner on the office network), and block merges if any scheme drops.
HighEvery bug report becomes a new phrase rule
Suggest
  1. Extract a structured query plan (scheme, metric, place + level, years, ranking direction + N, comparison) once, with the 4B classifier in guided-JSON mode, plus a deterministic normaliser for years, number words and place names.
  2. Let every later stage read that plan instead of re-reading the sentence.
  3. Keep the existing rules as overrides, merged into one shared vocabulary module.
Paraphrases then converge on the same plan, and the plan can be logged and tested.
MediumDocs don't match the code
Detail
  • CLAUDE.md says the 4B verifies SQL (it's the 30B) and that the re-ranker is on (it's off).
  • It says the privacy tables are prompt-only (they are blocked in code) and that the bank CSV is at the repo root (it's in raw_uc/).
  • Its test counts are stale ("27 files, 1,453 tests" vs 108 files, 3,650).
  • CURRENT_STATE says "uncommitted" 78 times and names commit f38ea1b, but everything except the KI-397 UI fix is committed in 6c95632. Its "Last updated" line is a 3,000-character log.
  • KNOWN_ISSUES reuses 7 IDs, and "FY24" has no ID.
Suggest
Keep CURRENT_STATE to one page of status, and move history to a changelog. Have a CI check that compares the model roles in CLAUDE.md with config.py. Assign KI numbers from one place.
MediumDecisions change too often, and parallel sessions collide
Detail
D-060 to D-066 all landed on 22 Oct, and some reverse each other (D-062 was replaced the same night by D-066). Several test runs failed only because another session was editing files mid-run. Commits are huge (115 to 1,098 files).
Suggest
One working tree per session (git worktrees). Small commits per fix, through pull requests. A weekly decision review in place of same-day reversals. Every behaviour decision becomes golden-set cases before code changes.
MediumNo load testing or monitoring
Suggest
Run a 20-user load test before go-live. It should cover latency rising from 5 s to 24 s at 4 users, the 60 s request limit and the 75 s UI cut-off. Add metrics for fail-open events, repair counts, verifier rejections and per-stage time, and alert on them.
