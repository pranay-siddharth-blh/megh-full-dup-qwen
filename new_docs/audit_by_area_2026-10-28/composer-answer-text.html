REPRODUCED, and worse than v1 said: there is also a 0.5% relative tolerance. This card merges v1 CMP-01 and CMP-03, because they edit the same 40 lines of compose_response.
The issueThe number check lets wrong figures through in five ways:
  • A figure within 0.5 absolute or 0.5% relative of any allowed value passes. A misquote of 6,563 on 1,494,437 passes, and so does 15.7% for 15.33%.
  • Coverage is a substring test, so "There are 11 pending" counts as stating 1. That is why the one-figure rule cannot catch it.
  • The one-figure rule runs only for Focus Plus and CM Elevate.
  • Number words are converted only after the check.
  • Nothing binds a number to its claim or unit: "82.91 lakh" for a percentage, or a gap stated as the larger value (CL-05), both pass.
The solution
  • Precision: a token with d decimals passes only if round(dv, d) == value for some data value; an integer token passes if it equals round(dv). Drop both blanket tolerances.
  • Coverage: compare against the answer's number tokens (_NUM_TOKEN), never substrings.
  • Apply the one-figure rule to every scheme, and convert number words before the check for every scheme.
  • Add _answer_unit_conflicts: a pct value followed by lakh, crore or ₹, or a lakh or crore value followed by %, counts as misquoted. A number directly followed by more, less, higher, ahead or below must be a computed difference from facts_nums.
  • Multi-row coverage: each asked measure (via CMP-02's _c12s_asked_metric) must appear, otherwise use _shaped_fallback.
Don't do this
  • Removing the skip for integers below 100. "top 5", "Tranche 4" and "100 days" would all fire. Token coverage catches "11 vs 1" instead.
  • Having code write the verdict sentence. _shaped_fallback already does that on failure.
Evidence
  • c12_answer_numbers.py:150-152 (both tolerances), :147 (integers below 100 skipped), :289-298 (f in ans).
  • c13:13 _ONE_FIGURE_SCHEMES, used at :222, :237 and :259-261. The number-word conversion runs for every scheme, but at c13:2627, after the checks.
