The architecture is sound, and the team is disciplined: 3,932 tests pass, every guard cites its incident, no regex anywhere, and SQL is checked on the parse tree. The product works for the common questions.

The risk is in the gaps between the checks. A wrong figure can still reach an officer with every check passing: some kinds of number are never compared to the data (CMP-04), a tolerance accepts near misses (CMP-01), and a village rewrite quietly turns a district total into a state total (SQL-09). Access control checks the SQL before the rewrites change it (SEC-09), reads place names as substrings (SEC-02), and a CTE named after a private table gets past the guard (SEC-08). Conversation memory is correct on the happy path, but error, stop and reset paths leave workers disagreeing (CTX-10, CTX-11, CTX-12).

The biggest quality lever is not a bug but a missing measurement: held-out NL→SQL accuracy is 43/74 (58%), and no automatic gate stops it from getting worse (QA-01, SQL-11).

What works today

Evidence: re-run today unless marked "from the docs".

  • Test baseline. 3,932 pytest passed, 0 failed, 3 skipped, plus 14/14 plain-script suites. I re-ran both today, on HEAD plus the uncommitted working tree.
  • SQL safety. Every model SQL goes through an AST guard (SQLGlot), not keywords. It refuses FOR UPDATE, information_schema, multiple statements, parse failures and private tables, including quoted and spaced names, ONLY and LATERAL. It then runs as a read-only login, inside a READ ONLY transaction, with a 1,000-row cap. One hole: SEC-08.
  • Repairs are re-authorized. Repaired SQL passes the same scope check as the first attempt (KI-183), and a restricted user's unparseable SQL is refused. The first attempt has a gap: SEC-09.
  • Auth basics. JWT: constant-time signature check, issuer and expiry checks, and malformed tokens give 401, not 500. The user row is re-read on every request, so deactivation takes effect at once.
  • Conversation state across workers. Postgres saves are versioned and refuse a stale write instead of letting the last writer win. Pending clarifications cross workers, and resume works even if the LangGraph checkpoint is gone. Tests: test_context_hardening.py, test_pipeline_graph.py.
  • Pause / resume design. The pause is an interrupt-only gate that does no expensive work, and the Session decides. Stale pause threads are swept, with a lock so two workers do not both sweep.
  • Caches. Answer caches are keyed by a scope fingerprint. Follow-ups, pause replies and context-dependent answers are never cached. A cache hit still updates the context (KI-319). The semantic cache compares places, years and contrasts.
  • Bounded memory. Sessions are an LRU capped at 5,000 with a TTL. Graph locks are pruned, turns are trimmed and topic headlines are capped. Qdrant memory has retention purges and a session filter.
  • Composer safety net. The fallback keeps the question's shape (ranking, compare, trend). A query's total row is not read as one more category. Mis-grouped digits are repaired (KI-062). A wrong list size is caught. Crore is rounded for display only. The streamed draft is always replaced by the checked final text.
  • Deterministic cross-scheme figures (D-066). Parameter-bound fixed queries. State totals come from a state-level query, never a sum of districts, and combined counts carry a caveat. One gap: the "lowest" wording, CMP-06.
  • Metric catalogue (D-071). Live on 26 Oct: 183 of 183 catalogue answers gave the same figure as the old path.
  • Live checks on record. From the docs, not re-run today (they need the VPN): the live context suite at 105/107 (the two failures, KI-406 and KI-407, wait on your decision); the smoke run, the same figures on all 6 schemes; the held-out NL→SQL set at 43/74 with 0 regressions (27 Oct).
  • Engineering discipline. No regex anywhere in app/ or frontend/src (grep is clean). Every guard cites the incident it fixes. CI runs the pytest files and the plain scripts separately, which avoids the KI-018 crash.

Where the problems come from

Most of the 72 tasks trace back to seven root causes. Fixing a task means fixing its instance. The "way out" line says how to stop the class from coming back.

R1

"Close enough" checks

Guards compare substrings or use a tolerance, or skip whole classes of numbers. Each check looks reasonable alone; together, a wrong figure can pass every one. "WEST GARO HILLS" matches inside "SOUTH WEST GARO HILLS"; LIMIT 2023 counts as a year; 6,563 off on 1,494,437 is "close"; 33% passes for 3.39%.

Tasks: SQL-01 CMP-01 CMP-04 CMP-05 SEC-02

Way out: Compare exactly, on structure: SQL through the SQLGlot tree, numbers as (value, unit, scale) against the result. Exempt only known prose patterns.

R2

Checks run at the wrong moment

A check runs on something other than what the officer finally gets: authorize before the rewrites, the faithfulness check on rounded values, the digest on capped rows, the fixed-answer paths without authorize.

Tasks: SEC-09 SEC-03 SQL-10 CMP-05 CMP-09

Way out: Put every guard on the last representation: authorize the SQL that runs, check numbers against unrounded rows, and know when a result was capped.

R3

Conversation state lives in four places

The in-process Session, the Postgres snapshot, the LangGraph checkpoint and Qdrant memory. The happy path keeps them in step. Error, stop, reset and expiry paths each skip one sync, and which worker serves the next request decides the answer.

Tasks: CTX-01 CTX-02 CTX-10 CTX-11 CTX-12 CTX-13 CTX-14

Way out: One rule: every exit from a turn either commits the whole snapshot or restores it. Write one test per exit path (success, error, stop, reset, expiry, cancel) that runs across two simulated workers.

R4

Measures carry no meaning

Code cannot tell whether a column is additive, which way is better, or what unit and scale it has. So percentages get summed, a higher delay is called "ahead", household-years are added to houses, and lakh is shown without ₹.

Tasks: CMP-02 CMP-06 CMP-08 CMP-03 UI-01

Way out: Next round: a small measure registry per scheme (unit, scale, additive, better-direction, label), read by the composer, the shapes, the cards and cross_figures. This round fixes the symptoms locally.

R5

Rewrites act on the whole tree

Deterministic SQL rewrites and guards look at every WHERE, or every name, instead of the node they mean. Village filters wipe the district in a CTE; a CTE name hides a private table.

Tasks: SQL-09 SEC-08

Way out: Scope every tree operation to the SELECT it is about, and add a CTE/subquery case to every rewrite's tests.

R6

Nothing measures accuracy automatically

3,932 unit tests prove the code does what it says, not that answers are right. The golden set (43/74) and the live context suite run only by hand, on the VPN.

Tasks: QA-01 SQL-11 QA-03 RAG-05

Way out: A nightly or pre-merge accuracy gate that fails on any regression, run on a VPN-connected runner.

R7

The process does not scale to parallel work

Much uncommitted work on Main. Shared logs of 1,100-1,400 lines that every change appends to. Two people and several sessions edit the same hot files: c13, c11, config.py, query.py, main.py.

Tasks: DOC-02 DOC-01

Way out: This plan: Step 0 commits everything and creates per-package regions; every file has exactly one owner; cross-package needs go through defensive contracts; integration happens once at the end.

The problem

topic_memory.checkpoint wipes every topic when the revision jumps by more than one. Every saved turn bumps the revision, but only graph turns run checkpoint. So these all wipe the topics:

  • a cache hit;
  • small talk handled by the conversation layer ("how are you?");
  • a typed "stop" with nothing running;
  • an early Stop;
  • every "Continue with …" tap after idle expiry, which restores a stale copy and keeps only one topic.
After a wipe, "go back to MGNREGA", the topic chips and digression recovery stop working. Separately, "go back to Mawphlang" never reaches the ledger, because parse_backward rejects a bare place name.

  • test_cache_hit_context.py:59 replaces sync_out with a no-op, and the in-process harness never calls it. That is why no test caught this.
  • parse_backward("go back to Mawphlang") returns None, while "go back to the Mawphlang one" works. _score already matches places correctly.

Medium2. CTX-10A failed turn leaves one worker's session out of step, and its pending question is lost therenew in v3

REPRODUCED with the real router _answer and session_sync, a stubbed model and a fake DB.

The problem

When a turn fails with 503, 504 or 502, the worker that ran it keeps a half-changed copy of the session. The saved copy in Postgres still has the pending clarification. The next reply therefore behaves differently depending on which of the four workers gets it.

What the officer sees

"How many MGNREGA person-days?" → bot asks "which area?" → officer: "West Garo Hills" → the gateway is busy (503). The officer retries "West Garo Hills". On the same worker (1 in 4) it is no longer a pause reply: it runs as a follow-up of the last answered turn, possibly another scheme. On the other workers it resumes correctly.

Where it comes from
  • _turn_context_stage (c14:263-346) clears session.pending_* at the start of the turn.
  • The except branches in routers/query.py:322-345 (_answer) raise without restoring the session and without calling sync_out.
  • On the next request, session_sync.sync_in (session_sync.py:88) sees rev <= session.rev and returns "current", so it keeps the damaged local copy.
The fix
  • In _answer, take snap = session.to_snapshot() before answer_question.
  • In every error branch (ModelBusy, DatabaseUnavailable, Timeout, UnsafeSQL, generic), call session.apply_snapshot(snap, session.summary) before raising.
Don't
  • Saving the half-changed state on error. The saved copy is correct; the local one is wrong.
Files this task edits
  • app/routers/query.py
Done when
  • New test: pause, then a reply whose data stage raises ModelBusyError. Afterwards session.pending_scope_q is the paused question again, and a second reply resumes it.

Medium3. CTX-01Conversation ownership and turn integritycarried from v2, re-checked

REPRODUCED: ensure('sid','alice') then ensure('sid','bob') returns alice's session. Severity lowered: the attacker must be logged in and hold another user's id (about 46 random bits), and figures are still re-authorised. This card merges v1 CTX-01 and CTX-03. · KI-399, KI-028

The problem

Nothing checks that a session id belongs to the caller. A user holding another's id inherits that chat's context, can ask "what did we discuss?" and receive the other user's questions, and overwrites the other user's state.
